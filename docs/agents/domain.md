# Domain docs

This repo uses one domain context across `apps/bot`, `apps/web`, and
`packages/shared`.

Before exploring domain behavior, read root `CONTEXT.md` when it exists and
relevant ADRs in `docs/adr/`. If absent, proceed without requesting them.
Create these files only when domain terms or decisions are actually resolved.

Use terms from the `CONTEXT.md` glossary in issues, specs, code and tests.
Call out any proposal that conflicts with an ADR instead of silently
overriding it.
